# 和同仁一起运行

这一版只做两种账号和用户隔离，不计算收益、不分佣、不收款。顾客小程序继续使用现有流程。

“用户”是保存资料、Wi-Fi 和二维码的业务记录；“同仁账号”是登录管理后台的账号。每位用户保留名称、简称、Logo、地址、联系人和电话，备注已删除。

## 启动与升级

- 新环境：按 README 配置 `.env`、启动 PostgreSQL、运行 `pnpm.cmd db:migrate` 和 `pnpm.cmd admin:init`，再启动 API 与管理后台。
- 服务端以 `INITIAL_ADMIN_USERNAME` 确定主账号。初始化账号和运行 API 使用同一配置。其他账号按同仁权限处理。
- 已有环境：先备份数据库，运行 `pnpm.cmd db:migrate`，同时更新 API 与后台。迁移 `0003_operator_ownership` 给旧账号保留管理员角色，旧用户的创建人、负责人为空，仍由管理员管理。
- 迁移 `0004_remove_user_notes` 删除历史备注列；其他资料、Wi-Fi、二维码、归属和统计保留。
- 同仁访问与你相同的后台地址。多人跨设备使用需要可访问的服务、HTTPS 和正确的后台 Origin/Cookie 配置；本地演示模式只用于测试，不作为多人共享数据服务。

## 最短使用流程

1. 管理员在“同仁账号”创建用户名和至少 10 位初始密码，私下交给同仁。用户名使用英文字母、数字、点、下划线或连字符。
2. 同仁登录，通过右上角账号菜单的“修改密码”更换密码并重新登录。
3. 同仁新建用户、填写资料和 Wi-Fi，生成二维码。用户创建人和负责人自动记为当前账号，无需选归属。
4. 管理员若需分配旧用户，在用户详情的“用户归属”选择负责人、填写原因，提交“转移用户”。二维码不变，Wi-Fi 不变，创建人不变。
5. 同仁离开时停用账号；登录会话立即撤销。用户和顾客二维码保留，管理员可继续管理或交给其他同仁。

## 权限

| 能力                                       | 主账号   | 同仁                                                 |
| ------------------------------------------ | -------- | ---------------------------------------------------- |
| 查看用户、搜索、分页、二维码预览/下载      | 全部用户 | 仅当前归属自己的用户                                 |
| 创建用户                                   | 允许     | 自动归属自己，默认启用、广告关闭                     |
| 初始 Wi-Fi 配置                            | 允许     | 仅自己创建、仍归属自己且启用的未配置用户；失败可重试 |
| 编辑用户、替换已有 Wi-Fi、启停用户及二维码 | 允许     | 不允许                                               |
| 生成二维码                                 | 允许     | 仅当前归属自己且尚无二维码的用户；不可覆盖或绕过停用 |
| 仪表盘、统计、设置、操作日志               | 允许     | 不允许                                               |
| 同仁账号管理、转移用户                     | 允许     | 不允许                                               |
| 修改本人密码                               | 允许     | 允许                                                 |

主账号的用户列表、详情显示用户创建账号，二维码列表和卡片显示二维码创建账号。转移负责人不会改变创建人。

停用账号、重置密码、本人修改密码都会撤销旧会话，重新启用账号不会恢复旧会话。修改本人密码需要当前密码；输错不会把正常会话退出。没有自助注册或管理员角色创建入口。

## 归属与记录

- `created_by_id` 只在新建用户时写入，不随转移变化。旧用户优先关联原始 store.create 日志，二维码关联 qrcode.generate 日志；没有可靠来源显示“历史记录，未记录”，不按当前负责人推断。
- `owner_id` 是当前管理权限依据；为空表示平台用户，同仁均无法管理。
- 转移记录保存在现有操作日志，包含旧/新负责人、操作人、时间和原因。没有修改或删除记录的管理接口。
- 用户修改在同一数据库事务内锁用户后校验权限。二维码生成会在调用上游前、写入前各检查一次，防止生成期间转移后旧负责人仍覆盖二维码。
- 扫码和广告事件是连接统计，不是收入或结算记录；未来结算应使用独立账务设计，不能从本版用户归属推算历史收益。

## 实际使用边界

账号协作可以在现有服务上运行；微信正式码、广告实际展示和一键连接仍需要真实配置与目标 AppID 真机验收。兼容 Wi-Fi 接口继续默认关闭，本次没有替你开启或宣称已通过正式版连接验收。
