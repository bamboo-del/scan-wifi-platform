# 管理后台与顾客扫码流程

本次按用户最新要求实现：管理操作在服务器后台完成，顾客小程序只显示扫码对应的 WiFi 名称、密码和连接按钮。用户要求跳过真机验收，实际手机连接能力尚未验证。

## 后台操作

1. 打开 `https://wifi.example.com`，使用管理员账号登录。
2. 在“商户管理”建立商户，再在“门店管理”新建所属门店。
3. 输入访客 WiFi 名称、密码并保存。已有门店可以在“Wi-Fi 管理”添加网络。
4. 在对应网络卡片点击“生成二维码”，下载小程序码或预览、保存 WiFi 贴。
5. 顾客使用微信扫一扫，进入 `pages/connect/index`。页面从服务器读取该码对应的网络信息，点击连接调用微信 WiFi 接口。

同一门店多个网络有各自的随机码，不会让顾客选择其他网络。密码更新不改变 scene；原贴码读取新密码。停用网络、门店、商户或二维码后，旧码不能继续获取凭据。后台列表不显示原密码；顾客页按本次要求显示明文密码，因此应配置商家授权公开给顾客的访客网络。

## 授权人员

每名授权人员可使用独立管理员账号；当前所有管理员具有同等管理权限，未实现分级角色。账号通过服务器现有 `admin-init` 命令创建，账号相同时不会覆盖密码。使用私密临时配置传入 `INITIAL_ADMIN_USERNAME` / `INITIAL_ADMIN_PASSWORD`，创建后清除临时凭据，禁止把密码放进命令行或聊天。顾客小程序不提供后台登录入口。

## 微信正式版本

后端固定生成 `release` 小程序码。微信正式版本必须包含 `pages/connect/index`；未发布时，真实制码会返回 `41030`，后台显示明确发布提示。不能用本地占位图替代。

在微信后台“开发管理 → 开发设置”添加 request 合法域名 `https://wifi.example.com`，然后在“版本管理”审核并发布本次上传版本。开发/体验版本及其二维码仅用于对应权限人员测试，不能作为顾客正式贴码。

前后端需同时显式配置 `MINIPROGRAM_ENABLE_LEGACY_WIFI_API=true`。小程序生产构建使用 `MINIPROGRAM_API_BASE_URL=https://wifi.example.com`，`MINIPROGRAM_LEGACY_WIFI_MANUAL_SYSTEM_CONNECTION=false`。默认关闭开关仍可显示信息，按钮会明确显示自动连接不可用。

成功状态依赖 `getConnectedWifi` 返回的 SSID 与目标一致，不把接口受理当作连接成功。微信版本、系统权限及平台接口可用性仍可能影响连接，本次没有真机验证结论。
